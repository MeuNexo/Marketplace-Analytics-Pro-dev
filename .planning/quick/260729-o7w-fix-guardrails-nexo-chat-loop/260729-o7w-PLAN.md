# Quick 260729-o7w — Corrigir guardrails do turno na EF nexo-chat

## Problema (observado por Wesley, 2026-07-29)

Pergunta estratégica no Consultor ("vale colocar R$47k de pedido na Pralana com lead time
+70d no pico da sazonalidade?") retornou **"Sem resposta."**.

Essa string é literal de `supabase/functions/nexo-chat/loop.ts:125`
(`reply: text || "Sem resposta."`). Ela só aparece quando o Gemini devolve um candidato
**sem `text` e sem `functionCall`** — ou seja, `parts: []`.

**Causa-raiz:** no Gemini 2.5 Pro os *thinking tokens contam dentro de `maxOutputTokens`*.
Com `maxOutputTokens: 1200` e `thinkingConfig.thinkingBudget: -1` (dinâmico), uma pergunta
multi-domínio (compra × sazonalidade × caixa × lead time) queima o orçamento inteiro
raciocinando e o candidato volta vazio com `finishReason: MAX_TOKENS`. Perguntas simples
passam; exatamente as perguntas de COO que a milestone Consultor CCO (Phases 103-105)
foi construída para responder é que morrem.

Agravantes no mesmo bloco de guardrails:
- `maxOutputTokens: 1200` é curto para uma análise CCO com números, mesmo quando funciona.
- `TURN_DEADLINE_MS = 25_000` — 2.5 Pro + thinking + 3-4 tools raramente fecha em 25s.
- `MAX_TOOL_ITERS = 5` — a pergunta do cenário Pralana precisa de `get_replenishment` +
  `get_projected_balance` + `get_dre_cash` + `get_purchase_suppliers`.
- Zero observabilidade: `finishReason`/`usageMetadata` não são logados, então o fallback
  não é diagnosticável pelos logs.

## Tarefas

### T1 — Redimensionar os guardrails do turno (`loop.ts`)
- `MAX_TOOL_ITERS`: 5 → **8**
- `TURN_DEADLINE_MS`: 25_000 → **75_000**
- `generationConfig.maxOutputTokens`: 1200 → **8192**
- `thinkingConfig.thinkingBudget`: -1 → **2048** (fixo; 2.5 Pro aceita 128..32768, nunca 0)
- **verify:** `grep` das 4 constantes; `npx vitest run supabase/functions/nexo-chat`
- **done:** valores novos no código e testes verdes

### T2 — Observabilidade do turno (`loop.ts`)
- Logar `finishReason` + `usageMetadata` (promptTokenCount/candidatesTokenCount/
  thoughtsTokenCount/totalTokenCount) por iteração — **só metadados**, nunca conteúdo,
  JWT ou API key.
- Log explícito quando o candidato voltar sem `parts` (o caso que gerou "Sem resposta.").
- **verify:** teste unitário novo cobrindo candidato vazio + finishReason MAX_TOKENS
- **done:** log presente e teste verde

### T3 — Atualizar testes existentes e deployar
- `loop.test.ts`: cap 5 → 8; asserção `thinkingBudget === -1` → `=== 2048` (mantendo a
  invariante `!== 0`, que é a que causa HTTP 400 no 2.5 Pro).
- Rodar suíte completa (`npx vitest run`) + `npx tsc --noEmit`.
- Deploy: `supabase functions deploy nexo-chat --project-ref ckcdevcxgvueywivefgx`
  (verify_jwt=true) — **deploy é do orquestrador**, não do executor.
- **done:** suíte verde, tsc 0, EF nova versão em prod
