# Plan 14-01: Infraestrutura — Migration + Índices + Upsert na Edge Function

## Goal

Ao final deste plano:
1. Existe `supabase/migrations/20260521180000_orders_indexes.sql` commitada no repo com os índices compostos para a tabela `orders`
2. A função `mercado-libre-integration` expande `order_items` em rows e faz upsert fire-and-forget na tabela `orders` com `comissao` (via `item.sale_fee`) e `frete` (via `order.shipping.cost` com fallback em `shipment.base_cost`) corretamente preenchidos
3. Após um sync manual pelo Dashboard, rows aparecem (ou são atualizados) em `public.orders` com `comissao` e `frete` não nulos para ordens `paid`

## Context

### Decisões críticas do research

- **NÃO criar tabela nova.** A tabela `public.orders` já existe no banco de produção (drift — sem CREATE TABLE nas migrations). O arquivo `20260520190000_orders_user_id_nullable.sql` faz `ALTER TABLE public.orders` sem CREATE prévio, confirmando o drift.
- **Migration apenas adiciona índices** usando `CREATE INDEX IF NOT EXISTS` — seguro de rerunner.
- **`comissao` vem de `item.sale_fee`** (campo no objeto `order_items[i]`, não `order.payments[0].marketplace_fee`).
- **`frete` usa dupla fonte:** `order.shipping.cost > 0` → valor do comprador; senão → `shipment.base_cost ?? cost.gross` (frete grátis/Full absorvido pelo vendedor).
- **Upsert key:** `(ml_order_id, ml_user_id, item_id, variation_id)` — suporta múltiplos itens por order.
- **Pattern fire-and-forget:** igual ao já usado para `productRows` e `stateRows` na mesma função (async IIFE, não bloqueia o response).
- **`fetchShipmentStates` atual** retorna apenas `{ uf: string; state_name: string }` — precisa ser ampliada para incluir `base_cost: number | null` e `cidade: string | null`.
- **Cap de 150 shipments** deve ser mantido. Budget de 20s deve ser mantido.
- O upsert usa `supabaseAdmin` (service role) — bypassa RLS, correto para background sync.

### Arquivos relevantes

- `supabase/functions/mercado-libre-integration/index.ts` — edge function a modificar
- `supabase/functions/sync-ml-orders/index.ts` — referência para lógica de `expandOrder` e campos exatos
- `supabase/migrations/20260520190000_orders_user_id_nullable.sql` — confirma schema de `orders` sem CREATE TABLE

### Task 3: Adicionar upsert de `orders` em `mercado-libre-integration` (fire-and-forget)

**File(s):**
- `/root/garment-glow-test/supabase/functions/mercado-libre-integration/index.ts`

**What:** Após o bloco de upserts existentes (`await Promise.all(upsertPromises)` na linha ~779), adicionar um bloco fire-and-forget que expande os orders em rows individuais por item e faz upsert em `public.orders`.

**How:**

Localizar a linha `await Promise.all(upsertPromises);` (por volta da linha 779). Imediatamente **antes** dela (para garantir que `orders`, `shipmentStates`, `user_id`, `sellerId`, `mlUserIdStr`, `organization_id`, `effectiveSellerId`, `syncedAt` estejam em escopo), inserir o seguinte bloco:

```typescript
// Orders upsert — fire-and-forget, não bloqueia o response
const orderRows: Record<string, unknown>[] = [];
for (const order of orders) {
  const dateCreated = order.date_created ?? null;
  const brtPedido = dateCreated ? toBRT(dateCreated) : null;
  const dataPedido = brtPedido?.date ?? null;

  // data_pagamento: primeiro pagamento aprovado
  const payment = order.payments?.[0];
  const dateApproved = payment?.date_approved ?? null;
  const dataPagamento = dateApproved ? toBRT(dateApproved).date : null;

  // comprador
  const comprador = order.buyer?.nickname ?? order.buyer?.full_name ?? null;

  // frete: buyer-paid first, fallback shipment base_cost
  const shipId = order.shipping?.id ? String(order.shipping.id) : null;
  const shipInfo = shipId ? shipmentStates.get(shipId) : undefined;
  const buyerCost = order.shipping?.cost != null ? Number(order.shipping.cost) : null;
  const frete = (buyerCost != null && buyerCost > 0)
    ? buyerCost
    : (shipInfo?.base_cost ?? null);

  const estado = shipInfo?.uf ?? null;
  const cidade = shipInfo?.cidade ?? null;

  // expand order_items
  for (const item of (order.order_items ?? [])) {
    const prod = item.item ?? {};
    const itemId = String(prod.id ?? "");
    if (!itemId) continue;

    orderRows.push({
      ml_order_id:     String(order.id),
      ml_user_id:      mlUserIdStr,
      organization_id: organization_id ?? null,
      seller_id:       effectiveSellerId ?? null,
      user_id,
      item_id:         itemId,
      variation_id:    prod.variation_id ? String(prod.variation_id) : "",
      sku:             prod.seller_custom_field ?? prod.seller_sku ?? null,
      titulo:          prod.title ?? null,
      listing_type:    item.listing_type_id ?? null,
      quantidade:      Number(item.quantity ?? 0),
      preco_unit:      item.unit_price != null ? Number(item.unit_price) : null,
      comissao:        item.sale_fee   != null ? Number(item.sale_fee)   : null,
      frete,
      status:          order.status ?? null,
      data_pedido:     dataPedido,
      data_pagamento:  dataPagamento,
      estado,
      cidade,
      comprador,
      synced_at:       syncedAt,
    });
  }
}

if (orderRows.length > 0) {
  (async () => {
    try {
      const orderBatches: typeof orderRows[] = [];
      for (let i = 0; i < orderRows.length; i += 200) {
        orderBatches.push(orderRows.slice(i, i + 200));
      }
      await Promise.all(
        orderBatches.map((batch) =>
          supabaseAdmin
            .from("orders")
            .upsert(batch, { onConflict: "ml_order_id,ml_user_id,item_id,variation_id" })
            .then(({ error }) => {
              if (error) console.error("Orders upsert error (non-fatal):", error);
            }),
        ),
      );
      console.log(`Orders: ${orderRows.length} rows saved`);
    } catch (e) {
      console.error("Orders async error (non-fatal):", e);
    }
  })();
}
```

**Notas de implementação:**
- O bloco usa `orders` (array de orders já deduplicado), `shipmentStates` (já populado por `fetchShipmentStates`), `mlUserIdStr`, `user_id`, `organization_id`, `effectiveSellerId`, `syncedAt` — todas estas variáveis já estão em escopo neste ponto do código.
- Não adicionar await — é fire-and-forget intencional para não aumentar latência do response.
- O `frete` aqui usa `shipInfo?.base_cost` que agora está disponível após a Task 2.
- Ordens sem `order_items` são silenciosamente ignoradas (o `for` não itera).
