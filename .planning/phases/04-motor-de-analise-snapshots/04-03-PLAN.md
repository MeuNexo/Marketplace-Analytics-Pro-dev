    4. saveSnapshot(input: SnapshotInput): Promise<AnalysisSnapshot>
       - Chamar computeAnalysis(input.orders, input.periodDays) para obter AnalysisResult
       - Montar objeto de inserção com campos snake_case para o Supabase:
         ml_user_id, organization_id, item_id, product_title, brand (ou null),
         period_start, period_end, price_curve (JSON.stringify do priceCurve array),
         price_gmv, price_neutral, price_margin, elasticity_pct, elasticity_class,
         strategy: null (usuário define depois via updateStrategy)
       - Chamar supabase.from('commercial_analysis_snapshots').insert(row).select().single()
       - Se error: throw new Error(error.message)
       - Retornar mapRow(data)
       - Atualizar estado saving: true antes, false depois (finally)

    5. fetchSnapshots(itemId: string, orgId: string): Promise<AnalysisSnapshot[]>
       - Chamar supabase.from('commercial_analysis_snapshots')
           .select('*')
           .eq('item_id', itemId)
           .eq('organization_id', orgId)
           .order('created_at', { ascending: false })
       - Se error: throw new Error(error.message)
       - Retornar (data ?? []).map(mapRow)
       - Atualizar estado loading: true antes, false depois (finally)

    6. updateStrategy(snapshotId: string, strategy: 'gmv' | 'neutral' | 'margin'): Promise<void>
       - Chamar supabase.from('commercial_analysis_snapshots')
           .update({ strategy })
           .eq('id', snapshotId)
       - Se error: throw new Error(error.message)

    7. Estado local com useState: saving (boolean, false), loading (boolean, false).

    8. Retornar { saveSnapshot, fetchSnapshots, updateStrategy, saving, loading }.

## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| componente React → saveSnapshot | Dados de entrada (orders, itemId, orgId) vêm do estado da UI — podem conter valores inválidos se formulários não validarem |
| supabase client → banco remoto | RLS valida organização; o hook confia no token de sessão para identificar o usuário |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Tampering | saveSnapshot organizationId | mitigate | RLS CHECK policy no banco rejeita INSERT se organization_id não pertence ao usuário autenticado; hook não precisa revalidar |
| T-04-08 | Repudiation | saveSnapshot | accept | created_at é DEFAULT now() no banco — não pode ser forjado pelo cliente; snapshot é append-only por design |
| T-04-09 | Elevation of Privilege | fetchSnapshots | mitigate | Query sempre inclui .eq('organization_id', orgId) além da RLS — dupla proteção; sem bypass via orgId de outra organização pois RLS bloqueia |
</threat_model>
