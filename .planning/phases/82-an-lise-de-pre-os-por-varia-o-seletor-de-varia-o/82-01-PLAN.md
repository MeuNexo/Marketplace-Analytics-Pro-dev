<objective>
Escrever a migration que estende a RPC `orders_price_timeseries` com um parâmetro
opcional `_sku text DEFAULT NULL`. Quando informado, a série passa a filtrar as vendas
por SKU (`AND o.sku = _sku`), permitindo que a UI (82-03) analise faixas/giro/cobertura de
UMA variação em vez do anúncio pai agregado. Quando `_sku` é nulo, o comportamento é
idêntico ao atual (Phase 79/81, análise do pai).

Purpose: o número de cobertura do pai é uma média que esconde rupturas por variação
(prova real: pai=6d na faixa baixa vs variação campeã SKU …420603=0d). Filtrar por SKU no
backend é o que torna a análise por variação precisa. Vínculo por **SKU**, nunca
`variation_id` (LIÇÃO: `orders.variation_id` casou 0/43 com o jsonb de estoque; `orders.sku`
= `seller_custom_field` casou 43/43).

Output: arquivo `supabase/migrations/20260682000000_orders_price_timeseries_sku.sql`. Este
plano SÓ escreve o arquivo — a aplicação em produção e o smoke são feitos pelo ORQUESTRADOR
via MCP no plano 82-02 (o gsd-executor não tem token de CLI nem MCP claude.ai do Supabase).
</objective>
