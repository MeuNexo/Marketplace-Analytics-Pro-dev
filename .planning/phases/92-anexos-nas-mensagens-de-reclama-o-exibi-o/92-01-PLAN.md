<objective>
Construir a camada de backend da exibição de anexos: (1) uma EF nova `ml-claim-attachment` que faz proxy autenticado do download binário do anexo do ML (o ML exige Bearer com o token do vendedor — não é URL pública), replicando EXATAMENTE o gate anti-IDOR das EFs irmãs; e (2) normalização aditiva do array `message.attachments` na EF `ml-claim-detail` para um shape estável `{ id, filename, type }`.

Purpose: o front não pode usar `<img src>` direto (não manda header Authorization) nem confiar em shape cru de anexo. O backend é a ponte segura por org.
Output: EF `ml-claim-attachment` (proxy base64) + `ml-claim-detail` normalizando attachments. Deploy + smoke via checkpoint (MCP).
</objective>
