## Objetivo

A edge function `ml-ads` na leitura de produtos do cache carrega TODAS as linhas do período
sem LIMIT, agrega em memória, e depois faz `.slice(0, 50)`.

Para 30 dias × N produtos → N×30 rows no heap da edge function.

**Fix:** Adicionar `ORDER BY spend DESC LIMIT 500` na query do DB.
A edge function ainda pode agregar por item_id, mas trabalha com ≤500 rows em vez de milhares.

---

## TAREFA 1 — Fix query de produtos no read path

**Arquivo:** `supabase/functions/ml-ads/index.ts`

Localizar o bloco de leitura de produtos (dentro do `Promise.all`):

```typescript
      // Lê todas as linhas do período e agrega por item_id no servidor
      admin
        .from("ml_ads_products_cache")
        .select("item_id,title,thumbnail,impressions,clicks,spend,attributed_revenue,attributed_orders")
        .eq("ml_user_id", mlUserId)
        .gte("date", dateFrom)
        .lte("date", dateTo),
```

Substituir por:

```typescript
      // Lê top produtos por spend — LIMIT defensivo evita carregar todo o período
      admin
        .from("ml_ads_products_cache")
        .select("item_id,title,thumbnail,impressions,clicks,spend,attributed_revenue,attributed_orders")
        .eq("ml_user_id", mlUserId)
        .gte("date", dateFrom)
        .lte("date", dateTo)
        .order("spend", { ascending: false })
        .limit(500),
```

**Manter** o bloco de aggregation por item_id abaixo — continua necessário para somar métricas de múltiplos dias do mesmo produto.

**Manter** o `.slice(0, 50)` no final — continua limitando o response a 50 produtos por produto para o frontend.
