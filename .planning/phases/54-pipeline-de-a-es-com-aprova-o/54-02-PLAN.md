<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend (authenticated) → proposed_actions | Membro inserindo proposta; RLS força status='proposed' + proposed_by=auth.uid() |
| frontend (owner) → proposed_actions UPDATE | Owner aprovando/rejeitando; RLS owner-only limita a approved/rejected |
| hook → consultor-actions EF | Disparo de execução só após approve; a EF reverifica owner/gate (defesa em profundidade) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-09 | Tampering | propose() forjando status/proposed_by | mitigate | RLS Phase 52 WITH CHECK (status='proposed' AND proposed_by=auth.uid() AND is_org_member); cliente não consegue burlar |
| T-54-10 | Elevation | approve/reject por não-owner | mitigate | RLS owner-only (get_org_role='owner'); UI esconde, mas RLS é a barreira real |
| T-54-11 | Tampering | cliente tentando setar executing/done/failed | mitigate | RLS bloqueia esses estados para authenticated (só service_role/EF) — Phase 52 |
| T-54-12 | Info Disclosure | leitura de ações de outra org | mitigate | Toda query org-scoped (.eq organization_id) + RLS SELECT is_org_member |
| T-54-13 | Elevation (mapa) | rule_key desconhecida virando ação errada | mitigate | buildActionFromInsight lança erro em rule_key fora de RULE_TO_ACTION (testado) |
</threat_model>
