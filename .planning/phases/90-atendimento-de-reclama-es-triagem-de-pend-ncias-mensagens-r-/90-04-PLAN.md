## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → ml_claim_templates (authenticated) | Direct CRUD guarded solely by org-first RLS (from Plan 90-02) |
| buyer_first_name → template body | PII flows into an editable message the user sends to that same buyer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-90-11 | Elevation of Privilege | writing/reading another org's templates | mitigate | hook always scopes organization_id from context + created_by from session; RLS (90-02) enforces server-side |
| T-90-12 | Tampering | template body injects unexpected variable → wrong data sent | mitigate | applyTemplate only substitutes known keys, unknown tokens stay literal (unit-tested); user reviews editable text before the confirm-send dialog |
| T-90-13 | Repudiation | who created a template | accept | created_by = auth.uid() recorded on insert; low-risk internal metadata |
</threat_model>
