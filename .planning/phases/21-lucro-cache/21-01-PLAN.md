## Task 2 — Fix Re-sync: cache-first, sync apenas para dados recentes

**Arquivo:** `src/pages/MercadoLivre.tsx`

**Problema:** O bloco `rangeSyncedRef` aciona `syncFromAPI` sempre que o range selecionado não tem dados no cache — mesmo para períodos históricos já sincronizados anteriormente.

**Causa:** `allDaily` vem de `useMLDailyQuery(fetchFrom, fetchTo)`. O `fetchFrom` é calculado em `useMLFilters` e pode ser amplo, mas o TanStack Query só tem os dados que foram carregados — se o usuário nunca carregou março, não há dados de março mesmo que o banco tenha.

**Fix correto:** Separar "dados históricos" de "dados recentes" e só sincronizar dados recentes automaticamente.

### Passos

1. **Remover o auto-sync por range vazio** — esse bloco é a causa principal do problema:

```typescript
// REMOVER completamente este useEffect (linhas ~222-235):
const rangeSyncedRef = useRef<string | null>(null);
useEffect(() => {
  if (!connected || dailyLoading || syncing) return;
  const todayStr = format(new Date(), "yyyy-MM-dd");
  if (currentTo < todayStr) return;
  const rangeKey = ...;
  if (rangeSyncedRef.current === rangeKey) return;
  const hasRangeData = allDaily.some(...);
  if (hasRangeData) return;
  rangeSyncedRef.current = rangeKey;
  syncFromAPI({ periodDays: 1 });
}, [...]);
```

2. **Manter apenas o auto-sync inicial** (já existe, já correto):
```typescript
// Manter — apenas no mount, 1x por sessão:
useEffect(() => {
  if (!user || storeLoading || autoSyncDoneRef.current || !connected) return;
  autoSyncDoneRef.current = true;
  // ... inventory + shouldAutoSync()
}, [user, storeLoading, connected, ...]);
```

3. **Ampliar `fetchFrom`/`fetchTo`** para cobrir 90 dias no carregamento inicial, sem re-sync:

Em `src/hooks/useMLFilters.ts`, verificar como `fetchFrom`/`fetchTo` é calculado. O objetivo é que o TanStack Query carregue uma janela maior de dados do banco de uma vez — assim ao mudar o filtro, os dados já estão no cache do React Query.

Se `fetchFrom` já cobre 90 dias, o problema é que o banco não tem os dados. Se o banco tem os dados (tabela `ml_daily_cache` populada pelo cron), o React Query vai buscá-los sem precisar de sync.

Verificar: `useMLDailyQuery` tem `staleTime`. Se os dados estão no banco mas o staleTime expirou, o React Query vai re-buscar do Supabase (não sync da API ML). Isso é rápido e transparente para o usuário.

4. **Aumentar staleTime de dados históricos:**

Em `src/hooks/useMLQueries.ts`, verificar o `staleTime` atual de `useMLDailyQuery`. Dados históricos (datas < hoje) nunca mudam — podem ter `staleTime: Infinity` ou 24h. Só dados de hoje precisam de `staleTime` curto.

Implementar via `gcTime` + `staleTime` separado por range:
```typescript
// useMLDailyQuery
staleTime: isHistorical(fetchTo) ? 24 * 60 * 60 * 1000 : 5 * 60 * 1000,
```

Onde `isHistorical(date)` retorna true se `date < today`.

5. **Ajustar `fetchFrom` para 90 dias no carregamento inicial:**

Em `useMLFilters.ts`, verificar `fetchFrom`. Se for apenas o `currentFrom`, ampliar para `max(currentFrom, today - 90 days)` para que o React Query carregue mais dados de uma vez. Isso evita múltiplas queries conforme o usuário muda o filtro.
