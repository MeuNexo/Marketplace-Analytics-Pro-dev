# 106-03 — Frontend

## Tarefas

### T1 — `useNexoChat`: conversas persistidas

**files:** `src/hooks/useNexoChat.ts`

- `send(text)` passa a mandar `{ org_id, conversation_id, message }` — não mais o array
  inteiro. A resposta traz `conversation_id` (criado no servidor no 1º turno).
- Novas ações: `listConversations()`, `openConversation(id)` (carrega do banco),
  `newConversation()`, `archiveConversation(id)`.
- Mensagem do usuário continua aparecendo na hora (otimista); em erro, faz rollback.
- Estado do React vira **cache** do servidor, não a fonte da verdade.

**verify:** `useNexoChat.test.tsx` — F5 simulado (remontar o hook) recupera a conversa
**done:** testes verdes

### T2 — UI de conversas no painel do Consultor

**files:** componente do painel do chat (localizar o consumidor de `useNexoChat`)

- Lista lateral de conversas (título + data), "nova conversa", arquivar.
- Mobile: lista em `Sheet`/drawer — o projeto é mobile-first (Phase 78) e o padrão de
  layout duplo exige ligar a interação **nos dois ramos** (mobile e desktop).

**verify:** vitest de render; checar os dois ramos de layout
**done:** conversa retomável pela UI

### T3 — Card de aprovação de memória

**files:** componente do chat + `src/hooks/useNexoMemory.ts` (novo)

- Quando o turno cria uma proposta (`status='pending'`), aparece um card:
  *"O Nexo quer lembrar disso: {title}"* com **Aprovar** / **Descartar** / **Editar**.
- Aprovar → `status='active'` + `approved_by`/`approved_at`. Descartar → `archived`.
  Editar → abre o texto antes de aprovar.
- Escrita direta via `supabase.from('nexo_memories').update(...)` sob RLS (padrão do
  projeto para config simples — igual `ml_mco_targets`, sem RPC).

**verify:** vitest do hook; prova de que `pending` nunca é injetado no prompt (backend, 106-02)
**done:** aprovação funcionando ponta a ponta

**verify:** tsc 0, vitest, build ok
