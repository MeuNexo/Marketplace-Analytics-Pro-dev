# 106-01 — Schema

## Contexto

Padrão de RLS a **clonar 1:1** de `20260719000000_ml_mco_targets.sql`: SELECT para
qualquer membro via `is_org_member`; INSERT/UPDATE/DELETE só `owner/admin/member` via
`get_org_role`; `organization_id NOT NULL REFERENCES organizations(id) ON DELETE CASCADE`.

## Tarefas

### T1 — Migration `nexo_conversations` + `nexo_messages`

**files:** `supabase/migrations/<ts>_nexo_conversations.sql`

`nexo_conversations`:
- `id uuid PK default gen_random_uuid()`
- `organization_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE`
- `user_id uuid NOT NULL` (dono da conversa)
- `title text NOT NULL DEFAULT ''` (primeiras palavras da 1ª pergunta; editável)
- `created_at / updated_at timestamptz NOT NULL DEFAULT now()`
- `archived_at timestamptz NULL`
- índice `(organization_id, user_id, updated_at DESC)`

`nexo_messages`:
- `id uuid PK`, `conversation_id uuid NOT NULL REFERENCES nexo_conversations(id) ON DELETE CASCADE`
- `organization_id uuid NOT NULL` (desnormalizado — deixa a policy de RLS direta, sem join)
- `role text NOT NULL CHECK (role IN ('user','model'))`
- `content text NOT NULL`
- `used_tools jsonb NOT NULL DEFAULT '[]'::jsonb`
- `created_at timestamptz NOT NULL DEFAULT now()`
- índice `(conversation_id, created_at)`

RLS: SELECT membro da org **E** `user_id = auth.uid()` nas conversas (conversa é pessoal,
não da org inteira — evita um membro ler o chat do outro). Mensagens herdam pelo
`organization_id` + EXISTS na conversa do próprio usuário.

**verify:** `SELECT` cross-org com JWT de outra org devolve 0 linhas; insert como viewer falha
**done:** migration aplicada em prod via MCP `apply_migration`, advisors sem issue novo

### T2 — Migration `nexo_memories`

**files:** `supabase/migrations/<ts>_nexo_memories.sql`

- `id uuid PK`, `organization_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE`
- `scope text NOT NULL CHECK (scope IN ('org','user'))` — fato da operação vs preferência pessoal
- `user_id uuid NULL` (obrigatório quando `scope='user'` — CHECK)
- `type text NOT NULL CHECK (type IN ('decision','preference','context','reference'))`
- `title text NOT NULL` (curto — é o que aparece na lista)
- `body text NOT NULL`
- `has_numbers boolean NOT NULL DEFAULT false` — **marca o fato perecível** (regra travada:
  fato com número é pista, nunca número atual)
- `status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','active','archived'))`
- `source_conversation_id uuid NULL REFERENCES nexo_conversations(id) ON DELETE SET NULL`
- `created_by uuid NULL`, `approved_by uuid NULL`, `approved_at timestamptz NULL`
- `created_at / updated_at timestamptz NOT NULL DEFAULT now()`
- índice parcial `(organization_id, status) WHERE status = 'active'` (é a leitura do turno)

RLS igual ao molde: SELECT membro da org (filtrando `scope='user'` para o próprio
`user_id`); escrita owner/admin/member.

**verify:** insert com `scope='user'` sem `user_id` viola CHECK; anti-IDOR cross-org = 0 linhas
**done:** migration aplicada em prod, advisors limpos

**files:** nenhum (validação via MCP `execute_sql`)
