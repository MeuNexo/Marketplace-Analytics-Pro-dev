# Plan 34-01 — Fix: KPI cards Markup, Custo Operacional e Impostos não carregam para "Hoje"

## Goal

Os 3 cards do `MLKPIGrid` que dependem de `kpiSummary` (Markup das Vendas, Custo Operacional,
Impostos) devem exibir valores reais ao filtrar por "Hoje" — da mesma forma que os outros
7 cards já exibem (Receita Total, Pedidos, etc.).

## Root Cause (diagnosticado via análise de código 2026-06-03)

**Chain completa do bug:**

1. Para "Hoje", a tabela `orders` pode estar vazia inicialmente (não há orders para o dia ainda).
2. `useAutoRecalc` detecta `costWaterfall === null && periodIncludesToday` → dispara
   `bulk-dispatch-sync-jobs` → aguarda 8s → chama `recalc-order-costs` → **invalida apenas
   `["ml", "cost-waterfall"]`**.
3. `useMLKPISummary` usa query key `["ml", "kpi-summary", ...]` — **nunca invalidada pelo
   `useAutoRecalc`**. A query disparou 1x ao montar o componente, retornou `null` (sem orders),
   e fica em stale com `null` para sempre naquela sessão.
4. No `MLKPIGrid`:
   - `markupValue` → `"—"` (sem kpiSummary)
   - `custoOpValue` → `"—"` (sem kpiSummary)
   - `impostosValue` → `"—"` (sem kpiSummary)
5. Os outros 7 cards vêm de `effectiveMetrics` (calculado de `ml_daily_cache`) → carregam
   normalmente via o auto-sync de `ml_daily_cache` que já existe.

**Por que o `cost-waterfall` funciona mas o `kpi-summary` não?**

O `MLCostCard` usa `costWaterfall` que tem invalidação após o recalc. O `MLKPIGrid` usa
`kpiSummary` que não tem invalidação — gap direto.

## Fix

### Task 34-01-A — `useAutoRecalc`: invalidar também `kpi-summary` após sync+recalc

**Arquivo:** `src/hooks/useAutoRecalc.ts`

Adicionar `queryClient.invalidateQueries({ queryKey: ["ml", "kpi-summary"] })` em **ambos
os paths** do hook (sync+recalc e recalc-only), logo após a invalidação de `cost-waterfall`.

```typescript
// Caso 1: após sync + recalc
queryClient.invalidateQueries({ queryKey: ["ml", "cost-waterfall"] });
queryClient.invalidateQueries({ queryKey: ["ml", "kpi-summary"] });   // ← ADD

// Caso 2: após recalc direto
queryClient.invalidateQueries({ queryKey: ["ml", "cost-waterfall"] });
queryClient.invalidateQueries({ queryKey: ["ml", "kpi-summary"] });   // ← ADD
```

### Task 34-01-B — `useAutoRecalc`: expor estado `isRecalcing` para loading nos cards

**Arquivo:** `src/hooks/useAutoRecalc.ts`

Mudar a assinatura para retornar `{ isRecalcing: boolean }` usando `useState` interno.
- `isRecalcing = true` ao iniciar a sequência (sync ou recalc)
- `isRecalcing = false` ao completar (após invalidação das queries)

```typescript
export function useAutoRecalc(...): { isRecalcing: boolean } {
  const [isRecalcing, setIsRecalcing] = useState(false);
  // ... no início de cada path: setIsRecalcing(true)
  // ... no finally: setIsRecalcing(false)
  return { isRecalcing };
}
```

### Task 34-01-C — `MercadoLivre.tsx`: passar `isRecalcing` para `MLKPIGrid`

**Arquivo:** `src/pages/MercadoLivre.tsx`

Capturar o `isRecalcing` do `useAutoRecalc` do período atual e passar como prop ao `MLKPIGrid`.
O `kpiSummaryLoading` já existe na prop — extender o loading para incluir `isRecalcing`.

```typescript
// Antes:
useAutoRecalc(costWaterfall, autoRecalcOrgId, resolvedMLUserIds, currentFrom, currentTo);

// Depois:
const { isRecalcing } = useAutoRecalc(costWaterfall, autoRecalcOrgId, resolvedMLUserIds, currentFrom, currentTo);
useAutoRecalc(monthlyCostWaterfall, autoRecalcOrgId, resolvedMLUserIds, monthlyFrom, monthlyTo);
```

No `MLKPIGrid`:
```tsx
<MLKPIGrid
  ...
  kpiSummaryLoading={kpiSummaryLoading || isRecalcing}
/>
```

### Task 34-01-D — `useMLKPISummary`: remover early-return agressivo quando period inclui hoje

**Arquivo:** `src/hooks/useMLKPISummary.ts`

O guard atual:
```ts
if (gross_revenue === 0 && cmv === 0 && total_frete === 0) return null;
```

Retorna null quando não há nenhum order ainda — correto para períodos históricos, mas
para "hoje" faz o hook never retry de forma eficaz (stale com null). Manter o guard mas
reduzir o `staleTime` de `5 * 60 * 1000` para `60 * 1000` quando o resultado é null,
ou usar `gcTime` menor para o cache de null values.

Alternativa mais simples: retornar um objeto "vazio" em vez de null quando gross_revenue = 0,
para que o re-fetch aconteça normalmente via invalidação:

```ts
// Não retornar null — retornar objeto com zeros para que invalidação funcione
// Early-return só se o request falhou de verdade (error path)
if (gross_revenue === 0 && cmv === 0 && total_frete === 0) {
  return {
    markup_ratio: null, markup_has_cost: false,
    custo_plataforma: 0, custo_operacional: 0, pct_custo_operacional: 0,
    gross_revenue: 0, total_tax: 0, has_tax_data: false, cmv: 0, cmv_has_cost: false,
  };
}
```

O `MLKPIGrid` já trata `kpiSummary` null com "—". Com objeto vazio, o resultado é o mesmo
visualmente para "sem dados", mas a invalidação vai re-fetch e popular os valores corretos
assim que os orders chegarem.

1. Ao selecionar "Hoje" em `/vendas`, após o auto-sync completar (~10-15s), os 3 cards

2. Durante o auto-recalc, os 3 cards mostram skeleton/loading (não "—" estático).

4. `npx tsc --noEmit` sem erros.
5. Sem regressão nos outros 7 cards do `MLKPIGrid`.
