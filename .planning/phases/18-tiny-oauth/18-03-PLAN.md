## Diagnóstico do problema

`MLSalesAnalytics` foi criado na Fase 17-03 copiando os sub-componentes de `MLRelatorios.tsx`.
Esses componentes usam `salesCache.daily` e `salesCache.hourly` diretamente — sem filtro de período.

O `salesCache` é um singleton de módulo populado pelo sync do ML. Ele pode conter dados de 7, 15 ou 30 dias (dependendo do último sync), independente do que o usuário selecionou no filtro de período no header.

**Resultado:** O usuário seleciona "Últimos 7 dias" mas os gráficos mostram 30 dias de dados — parece "errado" ou "fictício".

## Solução

Adicionar props `from: string` e `to: string` em `MLSalesAnalytics` e filtrá-los nos sub-componentes.

Como `MercadoLivre.tsx` já chama `getFilterDates(period, customRange)` para outros hooks, basta passar esses mesmos valores para `<MLSalesAnalytics />`.

## Como MercadoLivre.tsx obtém as datas de filtro

```typescript
import { useMLFilters, getFilterDates } from "@/hooks/useMLFilters";
// ...
const filters = useMLFilters();
// as datas já são computadas inline para outros hooks:
// useMLDailyQuery, useMLOrders, useMLKPISummary, useMLCostWaterfall, useMLOrdersByBrand
// todos recebem rangeFrom/rangeTo derivados de filters.period / filters.customRange
```

Ler MercadoLivre.tsx para entender exatamente como `rangeFrom`/`rangeTo` são passados para os outros hooks, e replicar o mesmo padrão.
