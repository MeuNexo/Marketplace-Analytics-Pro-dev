## TAREFA 1 — Migration: index de performance

**Arquivo:** `supabase/migrations/20260527120000_orders_perf_indexes.sql`

```sql
-- Index combinado status + data_pedido.
-- Todos os filtros principais incluem status IN ('paid','shipped','delivered')
-- e um range de data_pedido — esse index cobre os dois juntos.
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_orders_status_data_pedido
  ON public.orders (status, data_pedido DESC)
  WHERE status IN ('paid', 'shipped', 'delivered');

-- Index parcial para ml_user_id + data_pedido (filtros multi-account)
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_orders_user_data_pedido
  ON public.orders (ml_user_id, data_pedido DESC);
```

**Nota:** `CONCURRENTLY` evita lock na tabela durante a criação. Pode levar alguns segundos mas não bloqueia operações existentes.

## TAREFA 2 — Fix dual-scope em `ml-products-aggregated/index.ts`

**Problema atual (linhas 68–134):** A função executa dois SELECTs separados por loop de paginação:
1. Um com filtro `user_id IN [...]`
2. Outro com filtro `organization_id IN [...]`
Depois faz dedup no cliente. Resultado: 2× o número de queries necessário.

**Fix:** Unificar em uma única query que combina os dois escopos com `OR`.

### Localizar o bloco principal de query (dentro do `while (true)` loop):

```typescript
// ATUAL — apagar este bloco:
const { data: userPage, error } = await supabase
  .from("ml_product_daily_cache")
  .select(...)
  .in("ml_user_id", ml_user_ids)
  .gte("date", date_from)
  ...

let page = userPage || [];
if (organizationIds.length > 0) {
  const { data: orgPage, error: orgError } = await supabase
    .from("ml_product_daily_cache")
    .select(...)
    .in("organization_id", organizationIds)
    ...
  // merge + dedup no cliente
  page = merged.filter(...);
}
```

### Substituir por query única com `.or()`:

```typescript
// NOVO — uma query só combinando os dois escopos:
const orFilter = [
  ml_user_ids.length > 0
    ? `ml_user_id.in.(${ml_user_ids.join(",")})`
    : null,
  organizationIds.length > 0
    ? `organization_id.in.(${organizationIds.join(",")})`
    : null,
].filter(Boolean).join(",");

const { data: page, error } = await supabase
  .from("ml_product_daily_cache")
  .select("item_id, title, thumbnail, qty_sold, revenue, ml_user_id, date, synced_at")
  .or(orFilter)
  .gte("date", date_from)
  .lte("date", date_to)
  .order("date", { ascending: true })
  .order("synced_at", { ascending: false })
  .range(from, from + PAGE - 1);

if (error) {
  console.error("Query error:", error);
  return jsonResponse({ error: "Database query failed" }, 500);
}
```

**Manter** o global dedup abaixo (linhas 142–160) — ainda necessário para deduplicar rows que possam aparecer em ambos os filtros (ml_user_id e organization_id para o mesmo registro).

**Manter** todo o código de aggregation e response abaixo — apenas o bloco de query dupla muda.
