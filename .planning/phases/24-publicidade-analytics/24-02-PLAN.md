## Raízes dos bugs (diagnóstico)

### Bug 1 — Campos errados na query de ml_daily_cache
Em `useMLAdsDerivedMetrics.ts`, a query usa `.select("approved, qty")` mas os campos reais na tabela são:
- `approved_revenue` (não `approved`)
- `qty_orders` (não `qty`)

Resultado: retorna 0 para ambos → `total_revenue = 0` → `tacos_global = null`, `share_ads_pct = null`.

### Bug 2 — Tabela e campo errados em product_costs
Em `useMLAdsDerivedMetrics.ts`, a query usa `.from("product_costs").select("item_id, unit_cost")` mas:
- Tabela real: `ml_product_costs` (não `product_costs`)
- Campo real: `cost` (não `unit_cost`)

Resultado: query retorna erro silencioso → `costsMap` vazia → `acos_breakeven = null`.

### Bug 3 — Alertas mostram título completo
Nos 3 cards de alerta, `{p.title}` renderiza o título longo do produto.
User quer: `item_id` abreviado (ex: "MLB485106813") + `seller_sku` (ex: "BOTA-42-PR").

### Bug 4 — Sem filtros rápidos nas tabelas
Campanhas e produtos não têm chips de filtro por status/diagnóstico.

const filteredCampaigns = useMemo(() => {
  let list = campaigns;
  if (campaignSearch.trim()) {

    list = list.filter((c) => c.name.toLowerCase().includes(q) || c.id.includes(q));
