# Plan 32-01 — Fix: Lucro Bruto sem CMV e Impostos no Card Custos

## Goal

O card "Custos" em `/vendas` deve calcular Lucro Bruto descontando CMV e Impostos corretamente.
Atualmente CMV e Impostos ficam zerados por causa de um bug na RPC `get_cost_waterfall`.

## Root Cause (diagnosticado via debug mlcostcard-cmv-impostos-missing)

**Chain completa do bug:**

1. `get_cost_waterfall` RPC calcula `paid_revenue = COALESCE(SUM(receita_bruta), 0)`
2. Orders sincronizados antes da Phase 19 (migration 20260521300000) têm `receita_bruta = NULL` — o campo foi adicionado depois da criação da tabela
3. `SUM(NULL) = NULL` → `COALESCE(NULL, 0) = 0` → `paid_revenue = 0`
4. `useMLCostWaterfall.ts` linha 57: `if (paid_revenue === 0) return null` — hook retorna null inteiro
5. Em `MercadoLivre.tsx`:
   - `comissao` tem fallback: `costWaterfall?.total_comissao ?? ordersSummary?.total_comissao ?? revenue * 0.11`
   - `frete` tem fallback: `costWaterfall?.total_frete ?? ordersSummary?.total_frete ?? revenue * 0.05`
   - `cmv` SEM fallback: `costWaterfall?.has_cmv ? costWaterfall.cmv : null` → null quando costWaterfall=null
   - `impostos` SEM fallback: `impostosTotal` derivado de `costWaterfall?.has_tax_data` → null

**Resultado**: Lucro Bruto = Receita − Comissão − Frete − Publicidade (CMV e Impostos não descontados, inflado)

**Causa secundária**: `batch_upsert_orders` sobrescrevia `receita_bruta` e `receita_liquida` no ON CONFLICT sem COALESCE, então um re-sync de orders poderia apagar valores existentes se o novo valor fosse null.

## Fix

### Migration 20260601000000_fix_cost_waterfall_receita_bruta_fallback.sql

**Fix 1 — get_cost_waterfall RPC:**
Usa `COALESCE(receita_bruta, preco_unit * quantidade, 0)` para `paid_revenue`.
Orders com `receita_bruta=NULL` mas `preco_unit` preenchido contribuem para o total.
O guard `paid_revenue === 0` só dispara quando não há orders — comportamento correto.

**Fix 2 — batch_upsert_orders ON CONFLICT:**
Adiciona `COALESCE(EXCLUDED.receita_bruta, orders.receita_bruta)` — preserva valor existente
quando o novo for null, mesmo padrão já aplicado para `custo_unit`.
Mesmo tratamento para `receita_liquida`.

**Fix 3 — backfill histórico:**
```sql
UPDATE orders SET receita_bruta = preco_unit * quantidade
WHERE receita_bruta IS NULL AND preco_unit IS NOT NULL AND quantidade IS NOT NULL;
```
Popula orders antigos que ficaram sem `receita_bruta`.

## Success Criteria

1. Card "Custos" em `/vendas` exibe valores não-nulos para CMV e Impostos quando:
   - `ml_product_costs` tem entradas para os produtos vendidos no período
   - `ml_tax_config` tem configuração para a loja
2. `get_cost_waterfall` RPC retorna `paid_revenue > 0` quando há orders no período
3. Lucro Bruto = Receita Paga − Comissão − Frete − Publicidade − CMV − Impostos (sem inflação)
4. `batch_upsert_orders` preserva `receita_bruta` existente em re-sync
5. Orders históricos com `preco_unit` preenchido têm `receita_bruta` populado após backfill
