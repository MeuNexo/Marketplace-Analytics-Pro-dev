**RPC 1 — `get_dre_cash(p_org_id uuid, p_month date)` RETURNS TABLE (secao text, bloco text, categoria text, total numeric, n int)** [DREC-01, DREC-05]:
- CTE `params` (materializa constantes; CROSS JOIN nas demais): `mes_ini = date_trunc('month', p_month)::date`, `mes_fim_excl = (date_trunc('month', p_month) + interval '1 month')::date`, `hoje = (now() AT TIME ZONE 'America/Sao_Paulo')::date` (padrão BRT de `get_cost_by_month`).
- Seção `entrada` (bloco NULL), 5 linhas por LOCKED "Base de entradas" do 99-CONTEXT, todas de `cash_inflows` com `organization_id = p_org_id` e `release_date >= mes_ini AND release_date < mes_fim_excl`:
  - categoria `'bruto'`: `SUM(gross_amount)` com `release_date <= hoje`;
  - categoria `'liquido'`: `SUM(net_amount)` com `release_date <= hoje` (base real — refunds já vêm negativos no net, nada a subtrair);
  - categoria `'descontos_fonte'`: bruto − liquido (informativo);
  - categoria `'refunds'`: `SUM(net_amount) FILTER (WHERE status_mp = 'refunded')` com `release_date <= hoje` (informativo, "dos quais devoluções");
  - categoria `'a_liberar'`: `SUM(net_amount)` com `release_date > hoje` (informativo — a janela do mês já limita a ≤ fim do mês).
  Todos os totais com `COALESCE(..., 0)`; `n` = COUNT do mesmo filtro. Agregar `cash_inflows` UMA vez numa CTE materializada com `FILTER (WHERE ...)` por linha — nunca 5 scans separados.
- Seção `saida` (por LOCKED "Régua de saídas"): de `cash_outflows` com `organization_id = p_org_id AND status = 'paid' AND outflow_date >= mes_ini AND outflow_date < mes_fim_excl` (filtro literal `status = 'paid'` — Pitfall 3 do RESEARCH; `outflow_date` como régua, sem uso de `competence_date`), agrupado por `bloco = public.dre_bloco_for_category(category)` e `categoria = category`, com `total = SUM(amount)` e `n = COUNT(*)`. Retornar TODOS os blocos, inclusive `excluido` e `nao_classificado` — o filtro de cascata é responsabilidade da lib pura no frontend (espelho do guardrail de `dreCascade.ts`).
- Seção `previsao` (bloco NULL, por LOCKED "Imposto" — regime de caixa puro, SEM shift M+1; jamais reaproveitar a lógica `monthPlusOne`/`get_imposto_guia_by_competence` da DRE de faturamento — Pitfall 1 do RESEARCH), 3 linhas:
  - categoria `'imposto_guia_paga'`: `SUM(amount)` de `cash_outflows` `status='paid'`, `dre_bloco_for_category(category) = 'impostos_venda'`, `outflow_date` no mês M exibido;
  - categoria `'faturamento_mes'`: `SUM(COALESCE(o.receita_bruta, o.preco_unit * o.quantidade, 0))` de `orders` com `organization_id = p_org_id AND status IN ('paid','shipped','delivered') AND data_pedido::date >= mes_ini AND data_pedido::date < mes_fim_excl` — replicar o WHERE de `get_cost_waterfall` byte-a-byte (mesmo COALESCE, mesmos status, mesmo cast `::date`; filtrar SÓ por organization_id, sem parâmetro de lojas — recomendação A2 do RESEARCH), Pitfall 4;
  - categoria `'imposto_previsto'`: para k em 1..3, calcular `guia_k` (guias pagas no mês M−k, mesma régua da guia acima) e `fat_k` (faturamento do mês M−k, mesmo WHERE de orders); `taxa_k = guia_k / fat_k` é válida apenas quando `guia_k > 0 AND fat_k > 0`; `total = AVG(taxas válidas) × faturamento_mes`; se nenhuma taxa válida existir → `total` NULL (a linha DEVE existir com total NULL, o frontend mostra "—"). Implementar com `generate_series(1,3)` + CTEs pré-agregadas de guias e faturamento por mês, unidas por JOIN em `date_trunc('month', ...)` — proibido subquery correlacionada por linha (Pattern 3 do RESEARCH, timeout 8s do role authenticated).

**RPC 2 — `get_dre_cash_items(p_org_id uuid, p_month date, p_bloco text)` RETURNS TABLE (outflow_date date, supplier text, category text, amount numeric, document_number text)** [DREC-02]: seguir o exemplo pronto na seção "Code Examples" do 99-RESEARCH (SELECT direto de `cash_outflows` com `organization_id = p_org_id AND status = 'paid' AND public.dre_bloco_for_category(category) = p_bloco AND outflow_date` no mês, `ORDER BY amount DESC`). `p_bloco` é comparado por igualdade tipada — sem SQL dinâmico; valor fora dos 8 blocos simplesmente retorna 0 linhas (ASVS V5).

**RPC 3 — `get_dre_cash_history(p_org_id uuid, p_months int)` RETURNS TABLE (mes date, entradas numeric, saidas numeric, resultado numeric)** [DREC-03]: `v_meses = LEAST(GREATEST(p_months, 1), 12)`; gerar os últimos `v_meses` meses (incluindo o corrente) via `generate_series`; `entradas` = `SUM(net_amount)` de `cash_inflows` por `date_trunc('month', release_date)` com `release_date <= hoje` (BRT — mesmo cálculo da RPC 1, evita contar liberações futuras agendadas no mês corrente); `saidas` = `SUM(amount)` de `cash_outflows` `status='paid'` por `date_trunc('month', outflow_date)`, EXCLUINDO o bloco `excluido` (`dre_bloco_for_category(category) <> 'excluido'`) para que o resultado por mês seja o mesmo "RESULTADO DE CAIXA DO MÊS" da cascata; `resultado = entradas − saidas`; meses sem movimento retornam 0 (LEFT JOIN da série de meses com as agregações + COALESCE). Pré-agregar inflows e outflows em duas CTEs e juntar com a série por JOIN — nunca subquery por mês.

Comentário de cabeçalho da migration: 1 bloco `--` curto citando Phase 99 / spec `docs/superpowers/specs/2026-07-16-dre-caixa-design.md` e a decisão de régua (caixa puro: release_date / outflow_date+paid).
