# Plan 31-01 — Auto-sync CMV + Impostos + Pedidos Real-time

## Goal

O dashboard nunca exibe "s/ custo" ou "s/ config" quando há configuração disponível.
A página `/pedidos` sempre mostra dados recentes, sincronizando automaticamente ao abrir.

## Contexto do Problema

Wesley clarificou o escopo correto:

1. **CMV**: Nunca deve exibir "s/ custo". Se `has_cmv = false`, o sistema deve
   automaticamente recalcular custos via `recalc-order-costs` em background.

2. **Impostos**: A configuração fiscal existe (`ml_tax_config` tem 6 entradas). O
   `tax_amount` deve ser calculado no momento do sync de orders — se estiver nulo para
   pedidos do período, o sistema deve recalcular automaticamente.

3. **Pedidos real-time**: A página `/pedidos` deve sempre sincronizar dados de hoje ao
   abrir. O período padrão "Hoje" deve ter dados frescos sem precisar de ação manual.

## Success Criteria

1. Waterfall em `/vendas` nunca exibe "s/ custo" quando `ml_product_costs` tem entradas —
   dispara `recalc-order-costs` automático em background se `has_cmv = false`
2. Waterfall nunca exibe "s/ config" quando `ml_tax_config` existe para a loja —
   mesmo comportamento de recalc automático
3. `/pedidos` ao abrir: se não há orders para hoje, dispara sync automático de hoje
   antes de mostrar a lista (com loading indicator)
4. Sync automático de `/pedidos` não bloqueia a UI — roda em paralelo com o carregamento
   de dados históricos
5. `npx tsc --noEmit` sem erros

## Tasks

### Task 31-01-A — Hook `useAutoRecalc`: recalc silencioso quando CMV/imposto ausente

**Arquivo novo:** `src/hooks/useAutoRecalc.ts`

Lógica:
- Recebe `costWaterfall`, `orgId`, `mlUserIds`, `from`, `to`
- Se `costWaterfall` não é null E (`!has_cmv` OU `!has_tax_data`): invoca `recalc-order-costs` uma vez (sem bloquear UI)
- Usa `useRef` para não re-disparar na mesma sessão para o mesmo período
- Após recalc completo, invalida a query `["ml", "cost-waterfall", ...]` via `queryClient.invalidateQueries`

```typescript
// src/hooks/useAutoRecalc.ts
import { useEffect, useRef } from "react";
import { useQueryClient } from "@tanstack/react-query";
import { supabase } from "@/integrations/supabase/client";
import type { CostWaterfallData } from "./useMLCostWaterfall";

export function useAutoRecalc(
  costWaterfall: CostWaterfallData | null | undefined,
  orgId: string | null,
  mlUserIds: string[],
  from: string,
  to: string,
) {
  const queryClient = useQueryClient();
  const ranKey = `${orgId}-${from}-${to}`;
  const firedRef = useRef<Set<string>>(new Set());

  useEffect(() => {
    if (!costWaterfall || !orgId || !mlUserIds.length) return;
    if (costWaterfall.has_cmv && costWaterfall.has_tax_data) return;
    if (firedRef.current.has(ranKey)) return;

    firedRef.current.add(ranKey);

    supabase.functions
      .invoke("recalc-order-costs", {
        body: {
          ml_user_ids: mlUserIds,
          organization_id: orgId,
          date_from: from,
          date_to: to,
          only_missing: true,
        },
      })
      .then(() => {
        queryClient.invalidateQueries({
          queryKey: ["ml", "cost-waterfall", orgId, mlUserIds],
        });
      });
  }, [costWaterfall, orgId, mlUserIds, from, to, ranKey, queryClient]);
}
```

### Task 31-01-C — Auto-sync de hoje em `MLPedidos.tsx`

**Problema:** ao abrir `/pedidos` com período "Hoje", se não há orders para a data
corrente, a lista fica vazia sem informar o usuário ou tentar resolver.

**Fix:** após `loadOrders()` retornar 0 rows E o período incluir hoje, disparar
`sync-ml-orders` automaticamente para hoje antes de re-carregar.

Lógica a adicionar no `useEffect` que chama `loadOrders`:

```typescript
// Após loadOrders() — se resultado vazio e período inclui hoje, auto-sync
useEffect(() => {
  if (!connected) return;

  loadOrders().then(async (count) => {
    const today = new Date().toISOString().substring(0, 10);
    if (count === 0 && dateTo >= today) {
      // Auto-sync silencioso para hoje
      for (const mlUserId of resolvedMLUserIds) {
        await supabase.functions.invoke("sync-ml-orders", {
          body: { ml_user_id: mlUserId, date_from: today, date_to: today },
        });
      }
      loadOrders(); // recarrega após sync
    }
  });
}, [connected, loadOrders]);
```

Para isso, `loadOrders` precisa retornar o número de rows carregados.
Mudar assinatura: `async (): Promise<number>` retornando `allRows.length`.

**UX:** mostrar um toast "Sincronizando dados de hoje..." enquanto o auto-sync roda,
sem bloquear a tabela (que pode mostrar dados históricos enquanto aguarda).
