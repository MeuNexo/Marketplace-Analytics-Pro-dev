<objective>
Construir o "cérebro" testável do gatilho provisão→real, SEM tocar a página ainda (o wiring em MercadoLivre.tsx + a UI ficam no Plan 90-04). Três peças:

1. **`evaluateGuiaReal(rows)`** (pura, em `dreOperational.ts`) — recebe as linhas da RPC `get_imposto_guia_by_competence` (category/total/status) e decide se a guia é **real apurada**: existe ≥1 linha `paid` E **toda** linha `paid` tem `total > 1` (guarda de placeholder — os R$0,01 de junho reprovam). Retorna `{ hasGuiaReal: boolean, totalReal: number }` (soma só das linhas paid; 0 se não-real).
2. **`resolveTaxAndCmv(input)`** (pura) — decide, por mês, `impostosMes`/`cmvMes` + os selos `impostoFonte`/`cmvFonte`. Mês FECHADO (`hasGuiaReal`): imposto = `totalReal` (fonte "real"); CMV = cheio se disponível, senão cai pro custo médio com fonte "medio_fallback". Mês ABERTO: **byte-idêntico ao comportamento atual** (fonte "provisao"/"medio").
3. **`useImpostoGuia(competenceMonth)`** — hook espelhando `useDreOperational`, chama a RPC com a competência **S+1** (a régua é deslocada — quem calcula o S+1 é o Plan 90-04). Retorna o resultado de `evaluateGuiaReal`.
4. **`useMLCostWaterfall`** — threading de `cmv_cheio`/`has_cmv_cheio` no `CostWaterfallData`.

Zero-regressão é requisito duro (SC1): a card DRE é a mais visível do `/vendas`. `resolveTaxAndCmv` no caminho aberto DEVE reproduzir exatamente `(has_tax_data ? total_tax : null)` e `(has_cmv ? cmv : null)`.

Purpose: entregar lógica 100% coberta por testes puros antes de wirar na página.
Output: 2 libs/hooks novos + threading do waterfall + suíte vitest (aberto/fechado/placeholder/pending/cheio-ausente).
</objective>
