    Fluxo:
    1. Tratar `OPTIONS` com corsHeaders.
    2. Validar JWT: ler header `authorization` Bearer; `supabase.auth.getUser(token)`; 401 se invalido. Cliente criado com `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`.
    3. Validar body POST com zod: `{ item_id: z.string().min(1), ml_user_id: z.string().min(1) }`; 400 se invalido. (POST body, NAO query string — evita item_id em logs de URL.)
    4. Buscar token: SELECT access_token, organization_id FROM ml_tokens WHERE ml_user_id = body.ml_user_id AND access_token NOT NULL ORDER BY updated_at DESC LIMIT 1 (maybeSingle). 404 `{ error: "No ML token found" }` se ausente.
    5. Anti-IDOR: se `tokenRow.organization_id`, chamar `supabase.rpc("is_org_member", { _user_id: userId, _org_id: tokenRow.organization_id })`; 403 se falso. (Identico ao ml-reputation.)
    6. Buscar saude — tentar `/performance` primeiro, depois fallback `/health`:
       - GET `https://api.mercadolibre.com/item/${item_id}/performance` (caminho SINGULAR `item` — landmine 4) com `Authorization: Bearer ${access_token}`.
       - Se 200: normalizar a partir de buckets/variables/rules. `score` normalizado = `rawScore / 100` (landmine 2). Issues = rules com `mode === "OPPORTUNITY"` (ou `status === "PENDING"`). `source: "performance_api"`.
       - Se nao-200: GET `https://api.mercadolibre.com/items/${item_id}/health` (caminho PLURAL `items`). Se 200: `score` = `healthData.health` (ja 0-1, sem conversao). Issues = goals com `apply === true && progress < progress_max`. `source: "health_api"`.
       - Se ambos nao-200: retornar `{ item_id, score: null, level: null, level_wording: null, issues: [], source: "unavailable" }` com status 200 (modal NAO quebra — landmine resiliencia). Em caso de 401 da ML, pode retornar 401 `{ error: "ML token expired" }`. NAO chamar `ml-token-refresh` inline (landmine 5).
    7. Mapeamento PT-BR (incorporar como constantes no arquivo):
       - `GOAL_MAP`: objeto com os 10 goal IDs da tabela do RESEARCH (`price`, `financing`, `free_shipping`, `me2`, `technical_specification`, `picture`, `video`, `catalog_product_id`, `title`, `description`) -> `{ category, title, action_label }` em PT-BR.
       - `LEVEL_WORDING`: `professional->Profissional`, `gold->Ouro`, `silver->Prata`, `bronze->Bronze`, `standard->Satisfatoria`, `basic->Basica`.
       - Para issues de `/performance`: usar GOAL_MAP/mapa por `rule.key` quando conhecido; senao usar `wordings.title`/`wordings.label` da API como fallback (landmine 6 — melhor mostrar em ES do que ocultar uma issue real).
    8. Retornar o shape unificado `HealthResult` { item_id, score (0-1|null), level, level_wording, issues[], source }, onde cada `Issue` = { id, category, title, action_label, progress, progress_max }.
    9. Envolver tudo em try/catch; 500 `{ error: "Internal server error" }` no catch. `console.log` de diagnostico com user/store/source/issues.length (sem vazar token).

    NAO colocar blocos de codigo aqui — seguir o esqueleto do ml-reputation lido em read_first.
